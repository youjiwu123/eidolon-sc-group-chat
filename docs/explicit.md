# 成人向开关

这是给**部署者**用的开关，不是用户设置，页面上没有前端开关，也不按用户或角色单独设置。

## 开关与优先级

| 位置 | 写法 | 默认 |
| --- | --- | --- |
| `.env` | `EIDOLON_EXPLICIT_CONTENT=1`（`0` 或留空为关） | 关 |
| 管理后台 | `PUT /api/admin/config/explicit_content`，请求体 `{"enabled": true}` | 继承 `.env` |

后台的覆盖存在数据库的 `config_overrides` 表里，优先级高于 `.env`；在后台恢复这一项后，重新按 `.env` 的值生效。两者都只决定「这个部署允不允许成人向内容」，不决定某个角色能不能写：角色侧的年龄闸门在代码里，见下一节。

## 生效范围

- 文字回合与通话回合：两者共用 `engine._prompt`，所以开关同时作用于两边。
- 搭话（她主动开口）也走同一个 `_prompt`，同样生效。
- 照片不在此开关范围内：照片始终只有全年龄内容（ADR-0023），开关打开也不会改变生图提示词或画面内容。

## 年龄闸门（不可绕过）

`backend/src/eidolon/explicit.py` 里的 `explicit_prompt(character, allowed)` 按固定顺序判断：

1. 角色 `age` 缺失、或 `age < 18`：返回 `None`。未成年人**不产生任何提示词**，连「不要写」那句都不写，避免在未成年角色的提示词里出现任何相关暗示。
2. 成年角色、开关关闭：返回默认的「不写性描写，遇到这类要求含蓄带过或拒绝」。
3. 成年角色、开关打开：返回成人向场合的说明，同时要求保持她的性格、说话方式与关系逻辑，仍然不写伤害、强迫或违法内容。

年龄闸门直接读 `characters.toml` 里的 `age`，在代码里判断；因此：

- 改 `.env`、管理后台的 `config_overrides`，不会让未成年角色通过。
- 新加角色时，如果官方设定未满 18 岁，`age` 必须如实填写；闸门会据此拦住她。
- `age` 缺失表示未知，未知按未成年处理（安全默认）。

## 内容边界

开关只对成年角色、且只在部署者明确打开时生效。打开后也仍然：

- 保持角色原有的性格、说话方式、称呼与关系进展，不把角色变成另一个人；
- 不写伤害、强迫、违法内容；
- 受所用模型服务自身的条款与内容政策约束——部署者打开开关不等于模型服务一定接受。

## 相关测试

`backend/tests/test_explicit.py` 覆盖：未成年角色 + 开关打开仍返回 `None`、未知年龄返回 `None`、成年角色开关关闭/打开两种文案、`.env` 默认值与 `1`、后台覆盖优先，以及 `age` 的加载与非法值。
