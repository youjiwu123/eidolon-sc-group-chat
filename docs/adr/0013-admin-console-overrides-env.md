# 用 Web 后台管理部署，后台里改的配置存在数据库里、优先于 `.env`

原先部署者只通过命令行和 `.env` 运维，不在 Web 界面里操作（`PRODUCT.md` 的「次要角色」一节）。对公众开放以后，换模型、换 key、调限额、封禁刷量的用户都要登录服务器改文件、重建容器，所有人的通话都会被挂断。现在增加一个后台：只有管理者能进入，管理者是 `.env` 里列出的、用某些登录方式登录的普通用户，名单在后台里不能增减。后台里改的配置存进数据库，优先于 `.env`，不用重启：之后的新回合和新通话改用新值，进行中的通话不受影响。`.env` 继续作为默认值，每一项都可以在后台恢复成 `.env` 的值。

## Considered Options

- **后台直接改写 `.env` 然后重启**：配置始终只存在一个地方，但 `.env` 没有挂载进容器，容器还要能重启自己，而且每次重启都会挂断所有通话。
- **数据库是配置的唯一来源，`.env` 只留启动必需的几项**：不存在两处来源对不上的问题，但只用 `.env` 部署的人从此没法只改文件就上线。
- **只读后台**：没有覆盖带来的复杂度，但换 key、调限额仍然要上服务器操作，解决不了原来的问题。
- **后台另设口令登录**：和用户体系完全隔离，但多出一个攻击面，和 ADR-0006 去掉访问密钥的理由相同。

## Consequences

- 规则只有一条：后台里改过的值优先。部署者后来改了 `.env` 而后台已经覆盖了同一项时，`.env` 的改动不生效；后台在每一项旁边同时列出 `.env` 的值和当前生效的值，启动日志也会列出哪些项被后台覆盖了。
- 有些项永远不能在后台改，只能查看：管理者名单、`EIDOLON_SECRET_KEY`、OAuth 凭证、域名、WebRTC/TURN、备份、各种路径，以及向量化的服务和模型。前面几项改错了会把自己锁在门外，或者被攻破后台的人用来提升权限；向量化换了必须全部重新计算向量。
- 保存前会先试一下，试不通就不保存。重启时如果某项覆盖试不通（例如 key 已经被吊销），不拒绝启动，而是这一项改用 `.env` 的值，并在后台醒目地标出来，否则会因为进不了后台而没法修。这回退的是部署者自己的配置，与「自带密钥失败不改用部署者的 key」不矛盾。
- 部署者的 key 用 `EIDOLON_SECRET_KEY` 派生的密钥加密后存进数据库，所以也会出现在加密备份里。没有设 `EIDOLON_SECRET_KEY` 的部署，后台里的各种 key 只能看不能改。
- 没有设管理者名单的部署，后台整个不存在。
- 本地没有 OAuth（`EIDOLON_DEV_LOGIN=1`）时，开发者登录会给账号记一条 `github:<名字>` 的身份，所以 `EIDOLON_ADMINS` 写同一个名字，用那个名字开发者登录就是管理者；这条身份只有开发者登录那条路由会写，账号已经有 GitHub 身份时不写。
- 角色仍然由维护者在仓库里维护，后台不管角色，也看不到任何用户的对话、记忆和制作人档案。
