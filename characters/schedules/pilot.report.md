# 周表 pilot 报告：灯織 / 透 / 樹里 / 果穂

四个人的一周作息草案（`characters/schedules/<id>.week.draft.toml`），结构照
`schedules.mano.week.draft.toml`：65 个固定槽位 + 每人的随机池 + 只覆盖差异项的节日 + 10–14 条事件。
数据来源只有三处：`characters/schedules/<id>.stats.json`、`characters/facts/<id>.md`、
`characters/sheets/<id>.md`；学校部分是按学历补的（语料里学校只占 2–6%，见 `schedules.stats.md`）。

校验与模拟：`python .scratch/schedule/simulate_pilot.py`（exit 0，报告另存
`.scratch/schedule/simulate_pilot.report.txt`）。它断言：7 天 × 5 时段齐、每格 1–2 条、
scene id 全部存在于 `scenes.toml` 的 84 条、固定槽位不用 `sky`、池子只放日常场景且与固定槽位
不重叠、69 个日常场景一个不落、事件 chance 在 0.03–0.12、每个条目 `why`/`activity` 非空、
节日条目的日期与 `holidays.toml` 逐日一致；然后逐日跑完 2026 全年（1,825 次/人）。

## 3. 这批文件里定下的模型假设（接解析器前要定死）

1. **节日只覆盖差异项**：没写的节日回落到 `characters/holidays.toml` 的 `scenes`/`weights`。
   回落条目需要三样日历没有的东西——`priority`、窗口期 `chance`、占哪几个时段——按
   `schedules.model.md` 的优先级表 + 节日类型（公休占白天、祭典占晚上、情人节早晚、雏祭中午+晚上）定，
   和真乃文件里逐条写的值一致。**已在 `schedules.py` 里实现，见 §5.1。**
2. 窗口型节日的 `chance` 沿用真乃的取值（花見 .45 / GW .4 / 夏祭り .3 / お盆 .8 / 紅葉 .4）。
3. 每次通话独立 roll，所以**同一天里事件可以命中两次**（样例里元旦的宴会厅、juri 的诊察室+医院走廊）。
   真乃的模拟也是这样，不是这批新引入的。
4. 夜 22-2 只有一个格子，住宿类场景（`home` / `bedroom` / `dorm`）的占比一定被结构放大。

## 4. 感觉勉强 / 数据撑不住的地方

- **果穂的年龄**：任务书写「都是高中生」，档案写「小学六年级」。按档案排的。如果后面 23 人也
  照「高中生」批量生成，会有一批角色（果穂、可能的其它小学生/大学生）踩到同一个坑——
  建议生成器先读 `facts/<id>.md` 的「学校」那节再决定排不排高中。
- **休息室百分比不能当作息**：四人的前两名里都有休息室（灯織 23.7 / 透 9.9 / 樹里 14.7 / 果穂 30.4），
  但那是「对话发生的地方」。四份周表都只给它 4–6 格、且多数跟别的场景并列，模拟下来 3–9%——
  这是**故意不照搬**的，和真乃的处理一致。
- **「家」永远偏高**：夜里的格子必须有落点。四人里家最少的果穂，卧室也到了 10.0%（数据 2.1%）；
  真乃的 `home` 是 11.7%（数据 6.0%）。
- **樹里的宿舍没有 bg**：`dorm` 在 84 个场景里是她唯一说得通的住处，但语料里 0 句。
  「家 6.1%」这个数字撑不起「她住在宿舍」这个事实，只能靠档案。
- **学校场景**：四人 2–7% 的学校占比是全语料的偏向，不是角色特征。所以「哪一天上学」100% 是推断，
  四份文件的 `why` 里都写了「推断」。果穂的小学场景（操场/家庭科教室）在语料里接近 0。
- **「拉面」没有场景 id**：任务举例说樹里配拉面，但樹里的食物是肉铺可乐饼、章鱼烧、家庭餐厅；
  真正吃拉面的是透（担々麺 / サンマーメン / 家里做的酸辣汤番茄芝士拉面）。所以拉面给了透
  （`restaurant` 的固定槽位），樹里给的是商店街和家庭餐厅。
- **透的游戏厅**：任务举例说透配游戏厅，但她数据里 `arcade` 是 0——游戏是樹里的兴趣。
  透的版本改成「被雛菜拉去」，只放在事件里（0.045），不进固定槽位，避免把她写成玩家。
- **节日覆盖数量**：这批只写 11–13 条（真乃是 32 条全写）。没写的节日（成人式、敬老、万圣节、
  平安夜…）四人的选择和共享日历差别不大，写出来只是换个说法。如果要求「每人一份完整日历」，
  生成器得改成全覆盖——现在这份是「差异项 + 回落」。

## 5. 接进解析器（2026-10-26 实测）

### 5.1 节日回落（`backend/src/eidolon/schedules.py`）

- `load_schedules` 现在会把 `holidays.toml` 里**她没写的**节日补成回落条目：`scenes`/`weights`
  用日历的，`activity` 留空（`_holiday_choice` 取 `activities[0]`），`why` 是
  `回落：<name_ja>（<id>）`。写了的节日不补；优先级平手时她写的排在回落前面
  （model.md「平手取文件里靠前的」）。
- 回落要的三样日历没有，按 `schedules.model.md` 定死（写在模块 docstring 和常量注释里）：
  - `HOLIDAY_PRIORITY`：100 元日 / 95 初詣 / 90 公休 / 85 振替・国民の休日 / 80 大晦日・クリスマス /
    70 花見・お盆・夏祭り / 65 GW / 60 七夕・紅葉狩り・ハロウィン / 55 節分・ひな祭り・バレンタイン。
    表里没有的新节日按 `kind`：公休 90、振替・国民の休日 85。
  - `HOLIDAY_WINDOW_CHANCE`：花見 .45 / GW .4 / 夏祭り .3 / お盆 .8 / 紅葉 .4，其余 1.0。
  - `HOLIDAY_SLOTS`：公休/扫墓/花见/远足/GW 占白天三段；祭典（七夕・夏祭り・ハロウィン・平安夜・
    大晦日）和節分占晚上；情人节早上+晚上；雏祭中午+晚上；圣诞中午+晚上+深夜。
- 顺带修了两个「接不上」的问题：
  - `load_schedules` 原来只在排期表同目录找 `scenes.toml`/`holidays.toml`。草案在
    `characters/schedules/` 里，找不到就抛 RuntimeError，`app.py` 会静默回落预设行为。
    改成从 `path.parent` 往上找（`_nearby`），平铺和子目录两种放法都能用。
  - `app.py` 的 `schedule_of` 原来只找平铺的 `characters/schedules.<id>.week*.toml`；加上
    `characters/schedules/<id>.week*.toml` 两个候选（`week.toml` 比 draft 先看、平铺优先）。
- 后端镜像把 `src` 烤进镜像里，**只 `restart` 不会加载新代码**，这次用的是
  `docker compose up -d --build backend`。
