# 櫻木真乃 ・ 跨来源人设对照（页游 × SCSP）

> 同一间 283 Production、同一批角色，两种剧情模式：页游《アイドルマスター シャニマス》（enza）的 ADV 剧本，和《Song for Prism》(SCSP) 的剧情。
> 目的：分清哪些特质**两个来源都成立（核心）**，哪些只是**页游特有**或 **SCSP 特有**，给写提示词的人一个取舍依据。
> 本文件只新增，不改任何既有 sheet；脚本、样本、中间数据都在 `.scratch/corpus/`。

## 结论（三行）

- **20 条特质在两源都成立**，其中 15 条有计数支撑、频度差在 3pp 以内（促音是唯一明显偏移：37.0% → 28.9%）。
- **页游偏重 6 条**：手帳、占い、花・植物、むんっ、浇水施肥、風野さん／お弟子さん 这类称呼——除「花」外都是低频道具或单集语境。
- **SCSP 偏重 4 条**：自主練・レッスン、うとうと、布団・お日様の香り、センター自覚。**没有发现 SCSP 独有的新性格轴**；SCSP 的差异主要是「同一性格的频度与场景重心」不同（促音 −22%、ふふ −42%、あの +26%、レッスン ×2）。

### SCSP 提取与解析

- **下载**：从 `official-current-index.json` 取 `root/raw/s*_*.json`（5,133）、`root/raw/*_storylog.bytes`（528）、`root/raw/discussionscenario_9999.txt`（1），共 5,662 个 id，按 ≤100 个/批走 `POST /api/download`（`allow_unresolved: true, max_total_mb: 50`、`X-SCSP-Client: 1`），57 批，多实例并行（最多 5 个），轮询 `/api/jobs` 后从 `web-downloads/<jobid>/raw/root/raw/` 收文件。单个实例最多同时挂 5 个任务，超出返回 400。
- **storylog 二进制**：`[u8 version=1]` 后是记录流 `[int32 mark][int32 char_len][UTF-8 text][payload]`，长度按**字符**计；关键校验是 `mark == -(该文本的 UTF-8 字节数 + 1)`（名字 `真乃`→-7、`カメラマン`→-16、cue 28 字节→-29）。记录顺序是**台词 → 说话人名 →（有语音时）cue**；照这个顺序做交替解析，cue 只在有配音的行出现。
- **JSON**：`json.loads(text, strict=False)`；去掉尾逗号 `,\s*([\]}])`；1 个文件（`s70_09001090_00.json`）`text` 里有成对多写的引号，单独修一次。`text` 为 `Motion` 之类引擎指令的条目跳过。
- **说话人**：storylog 用名字记录（17,032 行有名字）；JSON 用 cue 的行号（`0010`）对齐条目 key 的末 4 位。**两种来源同时可得时 9,399 行完全一致、0 行冲突**——这是这套归属最硬的一次校验。
- **明文 ADV**：412 行，只有 天井社長 / プロデューサー，真乃 0 行。

### LLM 归纳

- 每源 **300 行**、分层抽样，`deepseek-flash`（reasoning `high`），每源 1 次调用，同一份 SYSTEM 提示词与 JSON 形状（speech / address / emotion / topics / avoid / habits，每条带 quote）。
- 页游样本沿用既有 pilot：seed `20261026`，300 行 / 209 集 / 117 个 bg，按剧情类型轮转；SCSP 样本 seed `20261027`，300 行 / 189 场次，按 `s01/s02/s06/s09/s10/s20/s40-s44…` 前缀轮转，单场次 ≤3 行、单前缀 ≤25%。
- **引用回查**：页游 30/30 条原句在页游语料里逐字命中；SCSP 29/29 条在 SCSP 语料里命中，**丢弃 0 条**（normalize 只去空白/换行和样本里的「／」）。

## 对提示词的建议

**可以直接写死（两源都验证过）**

1. 句尾「っ」+ です・ます + 「……」是她的基本音色：促音落在 30–37%、礼貌体 20% 上下、含省略号的行 76–88%。
2. 「ほわ」（6–8%）、「ふふ」（3.5–6%）、「あの／えっと」（7–8%）、首字结巴（7%）是四个最稳的口癖，跨源频度差都在 3pp 内或可解释。
3. 请求永远用「～でしょうか／～たいです／～てもいいですか」，不用命令形；被夸先慌（结巴/ほわ）再道谢；出错先道歉、先揽责；不自夸，退回「まだまだ」。
4. 话题盘：灯織・めぐる、散步和公园、鸟（鳩/ピーちゃん）、粉丝和舞台。称呼「プロデューサーさん」+「～ちゃん」。

**只当场景道具，别写进人设**

- 手帳（1 行）、占い（5 行 vs 1 行）、每天浇水施肥（单集）、風野さん／お弟子さん（单集语境）。
- 「花・植物」可以留成低频爱好（页游 1.2%），但不要让她逢人就聊花。

**SCSP 可以补的两点（只做情境，不做口头禅）**

- 工作/练习语境：自主練・レッスン（SCSP 是页游的 2×）——适合「安排练习、报告进度」这类对话。
- 身体感/生活细节：うとうと、晒被子、お日様の香り——低频，适合夜间或休息场景，不要当固定开场。

**频率参数（写提示词时可当硬约束）**

| 参数 | 页游 | SCSP | 建议取值 |
|---|---:|---:|---|
| 促音结尾 | 37% | 29% | 30–35% |
| です・ます | 20% | 21% | 20% |
| ほわ | 7.8% | 5.8% | 6–8% |
| ふふ | 6.0% | 3.5% | 4–6% |
| あの／えっと | 6.6% | 8.3% | 7% |
| 结巴 | 6.9% | 7.5% | 7% |

**不要照搬**

- 不要把「手帳」「占い」「浇水」写成习惯；不要把「風野さん」「お弟子さん」写进固定称呼。
- 不要把 SCSP 的「センター」叙事当成人设（页游里她几乎不谈位置）。
- 反过来，别因为 SCSP 里「ふふ」少就删掉笑声——页游 6.0%、SCSP 3.5%，两边都稳。

## 解析缺口与限制

1. **30.8% 的 SCSP 行没有说话人**：JSON 里没有配音的行（制作人/旁白）拿不到 cue，按规则记 unknown，没有猜。413 个场次根本没有 ACB。真乃的行不受影响（她的台词都有配音），但「全语料」的说话人覆盖率只有 65.2%。
2. **storylog 只覆盖 528 个 3D 场次**（17,086 行），JSON 覆盖 5,133 个 ADV 场次（53,678 行）；两者几乎不重叠（只有 2 个场次同时有），所以是相加而不是去重。
3. **2,881 行是 NPC 名**（雑誌編集者、MC、通行人……），映射不到 28 位偶像，单独记 `npc`；`unknown` 才是「完全没有说话人信息」。
4. **storylog 的 cue 与名字记录 9,399 行全部一致**，但这套校验只对「有配音的行」成立；无配音行只能靠名字记录。
5. **LLM 只各跑 1 次、每源 300 行**，没有人工复核；分类是我按「两源 LLM 输出 + 计数」做的判断，边界条目（花、占い、センター）可以再讨论。
6. **SCSP 语料只有页游的 1/4**（真乃 1,705 vs 7,299 行），比例差 <2pp 的不要当差异；页游侧本身也缺 22% 的集（无剧本），绝对占比只能当量级看。
